### Data Lifecycle(資料生命週期)：資料從建立到刪除的完整生命週期。  

---

**Data Lifecycle七大階段**  

1.	Create(建立)：建立客戶資料、建立訂單、建立原始碼等，這時會遇到第一個風險：資料建立錯或者一開始沒有做資料分類  
2.	Store(儲存)：資料放哪裡？Database、NAS、Cloud？這時就要開始思考資料是否需要加密、備份、權限問題。  
3.	Use(使用)：通常是最長的一段，資料可能每天修改、每天查詢，這時候最重要，要瘋狂的AAA之類的驗證。  
4.	Share(分享)：Email、API、USB、LINE。如果分享錯人是不是就是資料外洩？  
5.	Archive(封存)：例如五年前的交易紀錄，但法律要求保留七年，所以要封存。  
6.	Backup(備份)：可以歸類在Store裡面，但這部分很重要，所以特別提一塊來講。  
7.	Dispose(刪除)：若資料不是很重要就簡單刪除就好，若是重要的資料要做Data Sanitization(資料清除)。

---

**每個階段的不同風險**  

| 階段 |	常見風險 |
|------|----------|
| Create |	建立錯誤、分類錯誤 |
| Store | 沒加密、沒Backup | 
| Use |	權限太大、帳號共用 |
| Share |	寄錯Email、API洩漏 |
| Archive |	沒加密、保存太久 |
| Backup |	備份失敗、沒測試 |
| Dispose	| 沒清除資料 |

---

**Data Retention(資料保存)**  

資料通常會依據公司的Policy、商業需求或者是法律來決定要保存多久。  
例如公司規定：交易資料保存七年  

---

**Data Minimization(資料最小化)：只蒐集真正需要的資料。**  

在GDPR(一般資料保護規則)中非常重要。  
例如今天訂披薩，但app缺要求：GPS、聯絡人、麥克風，這樣完全不合理，通常只需要地址、名稱、電話就好。

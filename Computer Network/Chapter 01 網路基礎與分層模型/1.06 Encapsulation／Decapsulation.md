### Encapsulation / Decapsulation (封裝 / 解封裝)  

---

假設你在你瀏覽器裡送出Hello，資料會在你電腦一路往下  
```text
Application
↓
Data
↓
Transport
↓
Segment
↓
Network
↓
Packet
↓
Data Link
↓
Frame
↓
Physical
↓
Bits
到了對方電腦後
Bits
↓
Frame
↓
Packet
↓
Segment
↓
Data
```  

這兩個過程分別叫Encapsulation(封裝)以及Decapsulation(解封裝)。  

---

**為什麼要封裝**   

因為網路中的每一層都需要一些「額外資訊(Header / Trailer)」來完成自己的工作。  

例如Transport Layer需要知道「從哪個Port來？要道到哪個Port？」，所以每一層都會「在資料外面加上自己需要的控制資訊」。  

---

**Header是什麼**  

可以把它想成「這一層附加在資料前面的控制資訊」，例如  
```text
┌──────────────┬─────────────┐
│    Header    │    Data     │
└──────────────┴─────────────┘
```

**Header裡面可能包含**  
- Source
- Destination
- Sequence Number
- Protocol
- Length
- Flags
- Port等等

不同Layer的Header內容不一樣。  

---

**Trailer(拖車)是什麼**  

不是每一層都有Trailer，最典型的例子是：「Ethernet Frame的FCS」，所以Data Link Layer的Frame可以簡化成  
```text
┌────────┬──────────────┬─────────┐
│ Header │     Data     │ Trailer │
└────────┴──────────────┴─────────┘
```

---

**從Application開始**  

假設傳送Hello，此時它就是Data，這時還沒有TCP Header等等。  
```text 
┌──────────────┐
│    Hello     │
└──────────────┘
```

---

**進入Transport Layer**  

假設使用TCP，Transport Layer會加入TCP Header，TCP Header裡可能有Source Port、Destication Port、Sqeuence Number、ACK Number、Flags…，這整個東西叫TCP Segment。  
```text
┌──────────────┬──────────────┐
│  TCP Header  │    Hello     │
└──────────────┴──────────────┘
```

---

**進入Nerwork Layer**  

接下來到了IP，IP需要知道「這個資料從哪個IP來？要送到哪個IP？」所以加入IP Header，這整個叫IP Packet。  
```text
┌─────────────┬──────────────┬─────────────┐
│  IP Header  │  TCP Header  │    Hello    │
└─────────────┴──────────────┴─────────────┘
```

---

**進入Data Link Layer**  

因為Packet還不能直接在Ethernet LAN上傳，因為Ethernet還需要Source MAC、Destination MAC，所以再加上Ethernet Header，以及通常的FCS Trailer，這整個叫Ethernet Frame。  
 ```text
┌──────────────┬───────────┬──────────────┬─────────┐
│ Ethernet     │ IP Header │ TCP Header   │  Hello  │
│ Header       │           │              │         │
└──────────────┴───────────┴──────────────┴─────────┘
                                                │
                                             FCS
```

---

**最後進入Physical Layer**  

現在Frame還是一串資料結構，Physical Layer要把它轉成「可以在媒介上傳送的訊號」，例如Frame → Bits → Electrical Signal，最後變成101101010011，透過Ethernet Cable、Fiber、Wi-Fi等媒介傳出去。  

---

整個Encapsulation流程
```text
Application
     |
     | Data
     ▼
┌─────────────────┐
│      Hello      │
└─────────────────┘
     |
     | + TCP Header
     ▼
┌─────────┬─────────┐
│ TCP Hdr │  Hello  │
└─────────┴─────────┘
         Segment
            |
            | + IP Header
            ▼
┌─────────┬─────────┬─────────┐
│ IP Hdr  │ TCP Hdr │  Hello  │
└─────────┴─────────┴─────────┘
              Packet
                |
                | + Ethernet Header / FCS
                ▼
┌─────────┬─────────┬─────────┬─────────┐
│ Eth Hdr │ IP Hdr  │ TCP Hdr │  Hello  │ FCS
└─────────┴─────────┴─────────┴─────────┘
                       Frame
                         |
                         ▼
                        Bits
```

---

**每一層加入了什麼**  

| Layer |	加入的資訊 |	資料名稱 |
|-------|-----------|----------|
| Application |	Application Data | 	Data |
| Transport |	TCP/UDP Header |	Segment / Datagram |
| Network |	IP Header |	Packet |
| Data Link |	Ethernet Header + Trailer |	Frame |
| Physical |	轉成訊號	 | Bits |

---

**接收端開始Decapsulation**  

現在資料已經收到Server，Server收到的是Bits，Physical Layer把訊號還原成Bits/Frame，接著往上。  

---

**Data Link拆掉Ethernet Header**  

Server的網卡看到
```text 
┌──────────┬─────────┬──────────┬─────────┐
│ Eth Hdr  │ IP Hdr  │ TCP Hdr  │  Hello  │ FCS
└──────────┴─────────┴──────────┴─────────┘
```
Data Link Layer負責處理Ethernet Frame，確認「這個Frame是否是給我的？」然後把Ethernet Header與FCS處理掉，剩下  
```text 
┌─────────┬──────────┬─────────┐
│ IP Hdr  │ TCP Hdr  │  Hello  │
└─────────┴──────────┴─────────┘
```

---

**Networ Layer再處理IP**  

接下來IP Header + TCP Segment，IP Layer查看Destination IP是不是我的？處理完IP Header後，剩下TCP Segment。  
```text
┌──────────┬─────────┐
│ TCP Hdr  │  Hello  │
└──────────┴─────────┘
```

---

**Transport Layer再處理TCP**  

TCP Layer看到Source Port、Destination Port、Sequence Number、ACK…，它會根據TCP資訊「把資料交給正確的Application / Process」，最後去掉TCP Header，剩下Application Data。  
```text
┌──────────────┐
│    Hello     │
└──────────────┘
```

---

**完整Decapsulation流程**  
```text
Bits
 ↓
Frame
 ↓
去掉 Ethernet Header / Trailer
 ↓
Packet
 ↓
去掉 IP Header
 ↓
Segment
 ↓
去掉 TCP Header
 ↓
Data
 ↓
Application
```
會發現，每一層都只看自己要的東西  

| Layer |	關心的東西 |	功能 |
|-------|-----------|------|
| Ethernet |	Source MAC、Destination MAC |	我該把Frame給誰？ |
| IP |	Source IP、Destination | IP	Packet要往哪個Network？ |
| TCP |	Soutce Port、Destination Port、Sequence、ACK、Flags |	哪個Process / Port？ |
| Application |	Data本身 |	資料本身是什麼？ |

---

**MAC與IP為什麼都需要**  

雖然兩者有點像，但兩者解決的問題不同  

IP比較像「我要去什麼地方」。  
MAC比較像「在目前這個區域網路裡，這一樣要交給哪個網卡？」  

假設  
```text
PC A
 ↓
Router 1
 ↓
Router 2
 ↓
Server
```

IP Packet的Source IP、Destination IP通常會維持端到端的來源與目的地，但是每經過一個新的Layer 2網路，Ethernet Frame會重新建立。  

例如```PC A → Server```  

第一步```PC A → Router 1```  

Frame：  
Src MAC = PC A  
Dst MAC = Router 1。  <br>

IP：  
Src IP = PC A IP  
Dst IP = PC B IP。  


第二步```Router 1 → Router 2```  

Frame：  
Src MAC = Router 1  
Dst MAC = Router 2。  <br>

IP：  
Src IP = PC A IP  
Dst IP = PC B IP。  

大致上是這樣。  

---

**Router像「拆包再重新包裝」**  

Router不會把整個封包原封不動地「轉發Frame」  

Router收到Ethernet Frame，先處理Layer 2，然後```Frame → Packet```，查看Destination IP，接著查Routing Table來決定下一跳，然後重新封裝成新的Layer 2 Frame再送出去。  
```text
 
         Router
           │
Old Frame  │  New Frame
──────────→│──────────→
           │
           ↓
       查看 IP
           ↓
       Routing Table
           ↓
       決定下一跳
```

---

**這節最重要就這兩條**
   
Sender：Encapsulations  
```text
Data
 ↓
Segment
 ↓
Packet
 ↓
Frame
 ↓
Bits
```

---

Receiver：Decapsulation  
```text
Bits
 ↓
Frame
 ↓
Packet
 ↓
Segment
 ↓
Data
```
